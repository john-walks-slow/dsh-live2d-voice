## 二、HUD 拆层的等价性取证（auto-human 的 4 项核对）

1. **胶囊盒子逐像素等价**：把新增的触摸模式按钮隐藏、把全屏按钮临时挪回胶囊原位后，`.lv-capsule` 的 rect 与改动前 `.lv-hud` **完全相同**（`316.5, 620, 267×48`）；胶囊区域像素差异 **23/16740 = 0.14%**，最大通道差 19（抗锯齿级）。脚本 `capsule-baseline.mjs`（改前基线）、`capsule-equiv.mjs`（改后等价性）。
2. **绝对定位后代盘点**：`.lv-hud` 子树里唯一的绝对定位元素是 `.lv-pop`，其 containing block 从 `.lv-hud` 变成 `.lv-capsule`（同一个盒子），实测计算值 `bottom = padding-box(46px) + 12px`、右对齐一致 ✓；`.lv-btn` 自身 `position:relative`，所以 `.lv-btn.lv-mic-live::after` 的脉冲光环仍锚在按钮上。其余（`.lv-micbar` / `.lv-input` / `.lv-toast` / `.lv-center` / `.lv-calib-*` / `.lv-root:fullscreen`）都不是 `.lv-hud` 后代，锚点不受影响。
3. **几何读取面**：e2e 里没有任何一处读 `.lv-hud` 的 rect/offset；只有 `display:none` 隐藏（`verify-fullscreen-usable`、`verify-keyboard-squish` 做像素测量时用——层化后隐藏整层会连带隐藏角落簇，模型 bbox 更干净）、存在性布尔（`verify-live`/`verify-standalone*`）与后代点击选择器（`.lv-hud button[title*=…]`、`.lv-hud .lv-mic`、`.lv-hud [title*="快捷调整"]`）——**0 处 e2e 改动**。
4. **淡出与可达性**：`layer-checks.mjs` 4/4 —— root layer `pointer-events:none`、`.lv-pop` 锚点、角落簇淡出 0.45、`focus-within` 提亮 ✓（`.lv-hud.lv-mic-live.lv-faded` 例外只抬胶囊）。

## 三、视线方向度量与阈值标定（T8）

- 方法：手指固定在画面左 12% / 右 88% 处按住，各等视线 settle 900ms 后截帧；用 PIL（复用 `verify-fullscreen-usable` 的角落采样背景法）在**上半屏**取非背景像素的**水平质心**（按屏宽归一）。
- 实测（haru / 900×700 / 第一人称）：`left=0.3575`、`right=0.6466` → **位移 0.2891**；同一位置连拍两帧漂移 **0.0002**。
- 阈值取 **0.05**（噪声的 250 倍、信号的 1/6），方向断言（右 > 左）同时成立。数值写进套件注释。

## 四、未覆盖 / 说明

- **三个 GUI 全屏套件未通过（环境所限，非本改动回归）**：`verify-fullscreen-usable` / `verify-fullscreen-keyboard` / `verify-keyboard-squish` 都需要实例里存在**真实 chat 会话**（点 `[role="treeitem"].sessionRow` → 会话页签 "Live2D"），最小 e2e 实例只有空会话，故在 `waitForSelector('.lv-root .lv-stage canvas')` 超时失败——失败发生在与 HUD 交互之前，与本改动无关。等价覆盖由 `verify-standalone-fullscreen`（走 standalone 入口的角落全屏按钮 + 原生全屏 + 几何）与 `verify-touch-mode` T5a/T5b 承担。
- **玩家化身**没有独立的手势/空闲调度；**鼠标**不做 flick；**参数面板/表情选择器**不在本轮（计划 §二非目标）。
- 主观手感（跟手程度、滑动阈值是否顺手、角落按钮位置）请用户真机确认，见 §五。

## 五、真机验收清单（触摸模式）

> 归因基线（线上跑的就是被检过的那一版、sha256 与配置写入的如实记录）见 `261010-live2d-touch-mode.baseline.md`。

每条都写了**期望现象**，摸的时候对着看；哪条不符就把编号告诉我。

| # | 操作 | 期望现象（不符即为问题） |
|---|---|---|
| 1 | 打开触摸模式：工具条上的手指按钮，或 ⚙ 系统设置卡里的「触摸模式 (touchMode)」开关 | 按钮点亮、设置卡下拉变成「开启」；**首次**开启时底部弹出一行提示（"角色跟着你的手指看…"）约几秒后消失；刷新页面后开关**仍是开启**（这是 host 侧持久化生效的判据） |
| 2 | 手指按住屏幕任意位置并缓慢移动 | 角色**头与眼同时**转向手指方向，跟手无明显延迟（<0.2s 的滞后可接受）；手指移到最左/最右时转向角度接近上限但不"翻白眼"；**不要**出现模型整体平移 |
| 3 | 抬起手指 | 视线在**约 0.5 秒内平滑**回到摄像头视线（开着眼动追踪）或回到正视（没开）；全程**无跳变**、无突然复位；不会卡在手指最后的位置 |
| 4 | 单指拖动；然后两根手指捏合/拖动 | 单指**不再**平移模型（只有视线跟手）；双指能平移与缩放；双击仍复位视图 |
| 5 | 轻触角色的头/身体；再快速左右、上下划动 | 轻触触发它自带的 `Tap` 动作（一次轻触一个动作，不乱播）；滑动触发 `Flick` 系列动作（左右能分别触发左右；上下若模型没有对应动作会退化成它自带的另一个手势动作）；**连续快速滑动不会打满动作队列**（约 0.4 秒内只算一次） |
| 6 | 桌面鼠标（不用按键）在画面里移动；再按住拖动 | 鼠标移到哪角色看哪（与开摄像头时同一套幅度）；按住拖动**仍是平移**、滚轮缩放；鼠标快速甩动**不会**触发手势动作（鼠标没有 flick 语义） |
| 7 | 点右上角簇的全屏按钮；退出全屏 | 按钮在右上角、不被系统状态栏/下拉手势挡住；进入沉浸全屏后画面铺满、比例不变形；再点能退出（不留死路） |
| 8 | 关掉触摸模式后重复第 2 条 | 单指拖动恢复为**平移**模型、角色不再跟手指、也不写跟手向量；重开则恢复第 2 条行为 |

**刻意行为（不是 bug，不用报）**：
- 语音对话中角色正在播剧本动作（LLM 打的动作标签）时，轻触/滑动会被**静默忽略**（该动作播完再划即可）——手势与点击同为 NORMAL 优先级，不抢剧本动作。
- 连续快划有 400ms 冷却，第二次滑动在冷却窗口内不生效（防刷屏）。
- 触摸模式开启时单指不平移是设计（平移交给双指）——手感不习惯就先关掉开关，它会记住。

**已知边界（不算验收项）**：玩家化身（第三人称/视频通话里你的小窗）没有独立的手势/空闲调度；鼠标没有 flick；表情/参数面板不在本次范围。

## 八、手感四项判定线（真机照做，缺一条即为不可判）

| # | 前置条件 | 操作步骤 | 期望现象 | 判定线（不满足 = FAIL） |
|---|---|---|---|---|
| 2 | 触摸模式开；第一人称单模型；模型库选中 `haru`（或任意有时间轴的模型）；无语音播放 | ① 手指按在画面左侧 1/4 处保持 1 秒；② 保持按压，用 **≥1 秒**的时间匀速横向划到右侧 1/4（约 400px）；③ 在右侧保持 2 秒 | 头部与眼球**连续**跟随手指方向，中途不回弹、不跳格；到两侧时接近该模型角度上限（不是只动一点点，也不"翻白眼"）；**模型整体位置不动** | **主观**：肉眼能看出"头/眼明显落后于手指"或移动中途卡顿/跳变即 FAIL。**可选客观**：60fps 录屏，手指停止移动后头部到达该方向最大偏转的时间 **> 300ms** 即 FAIL（低于此不可靠，不设硬指标）；两侧端点的水平质心差应 ≥ 0.05 屏宽（e2e T8a 用的同一口径） |
| 3 | 同第 2 条；若开了摄像头视线追踪更好（能看交接） | ① 按住画面右侧 1/4 保持 1 秒让视线偏到右侧；② 抬手，目不转睛看 1 秒 | 视线在**约 0.5 秒**内平滑滑回摄像头视线（未开则回正视），全程无跳变、无突然复位、不会卡在右侧 | **主观**：出现"啪"一下的瞬移、或抬手后 1 秒仍停在右侧即 FAIL。**可选客观**：抬手后每 180ms 截帧算头素质心（e2e T8d 同一口径），单帧位移 **> 0.18 屏宽** 即判跳变 FAIL；末帧相对抬手帧的位移应 ≥ 0.05 |
| 5 | 触摸模式开；选**带 Tap 与 Flick 的模型** `official/izumi`（只有 Flick 的换 `chitose`，只有 Shake 的换 `oc/luna`） | ① 轻触头部一次；② 等动作播完，快速右划一次；③ 等动作播完，快速左划一次；④ 接着 0.5 秒内连续快划 5 次 | ① 触发一个自带动作（头/身体动一下），**不是**连播多个；② 右划触发右向手势动作；③ 左划触发左向；④ 连续快划**不会**连播 5 个（约 0.4 秒窗口内只认一次） | **判定**：轻触一次播多个动作 = FAIL；左右划方向反了 = FAIL；连续 5 次快划触发 ≥ 3 个动作 = FAIL（`dataset.lvGesture` 可对照，见 §七）。模型没有对应方向组时退化成它自带的另一个手势动作**不算 FAIL**（设计如此） |
| 6 | 桌面浏览器（鼠标），触摸模式**开** | ① 不按任何键，鼠标在画面里从一侧缓慢移到另一侧；② 按住左键拖动 200px；③ 快速甩动鼠标（不按键）左右各一次；④ 滚轮滚动 | ① 角色视线跟随鼠标；② 按住拖动**平移**模型（不是转视线）；③ 甩动**不触发**任何手势动作；④ 滚轮缩放 | **判定**：① 无跟随 = FAIL；② 拖动变成转视线或不动 = FAIL；③ 甩动触发了动作 = FAIL（鼠标没有 flick 语义）；④ 滚轮无缩放 = FAIL |

**不属于判定范围**：动作本身好不好看、动作时长、跟手"手感偏好"（喜欢更快/更慢）——这些是主观偏好，记成 issue 讨论，不算 FAIL。

## 九、35 项断言的覆盖面分类（不夸大）

| 类别 | 条目 | 说明 |
|---|---|---|
| 真实浏览器交互路径（合成指针/鼠标事件进入页面 → 读行为后果） | T1a/T1b/T1c、T2a/T2b、T3、T6、T4/T4b、T5c、T7、T4a/T4b/T4c、T5、T6a/T6b、T11、T12、T13（共 20 条） | 事件真的过了页面的指针/点击处理链，断言读的是行为后果（`lvTouchLook`/`lvTransform`/`lvTap`/`lvGesture` 契约、配置文件落盘、`fullscreenElement`）。**其中 T12/T13 是"交互后读状态"**，只证明"双击确实复位了视图""按钮确实进了/出了全屏"，**不构成手感兜底** |
| 视觉度量（真实交互 + 截图 + PIL 质心） | T8a、T8b、T8c、T8d、T8d2（5 条） | 唯一触到"像素级效果"的一类：头随手指方向位移 ≥0.05、null 漂移 <0.05、方向正确、回落单帧 ≤0.18 且总量 ≥0.05 |
| 纯 DOM/CSS 状态检查（无交互路径） | T5a、T5b、T9（3 条） | 布局几何、`pointer-events` 计算值、页面错误——**与"能不能用"无关**，只防结构性回归 |
| 纯函数（node 直接跑，无浏览器） | T10a–T10g（7 条） | 滑动判定阈值、主轴方向、组回退链 |

结论：**手感（跟手滞后、回落平滑度、误触、鼠标 hover 的"自然感"）没有一条 e2e 能替代**，必须真机按 §八 走；
e2e 覆盖的是机制与结构（20 条交互路径 + 5 条视觉度量），不覆盖主观手感。
