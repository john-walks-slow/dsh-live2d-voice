# 261010-motion-preempt 用户验证

## 验证说明

- 验证对象：**手势被静默丢弃**的修复——触摸模式下"上一次手势/点击起的动作还在播"时，新的滑动/点击改为**抢占**；
  只有 **AI 剧本动作**在播时才拒绝，且拒绝会**闪一下 HUD 手指按钮**。
- 环境/前置条件：真机（触屏）+ 线上 dsh；触摸模式打开；模型用 **izumi**（片长最长：FlickLeft 1.9s / FlickRight 2.6s / Shake 4.1s，
  是最容易复现死区的模型）。桌面鼠标只能验证"视线/剧本拒绝"，滑动抢占用触屏更直观。
- 机制面证据（不需要真机、已跑绿）：`e2e/verify-touch-mode.mjs` 50/50、`e2e/verify-tap.mjs` 11/11、
  幅度探针 `docs/features/261010-live2d-touch-mode/motion-preempt-amplitude.mjs`（真抢占无跳变 + 30° 负对照判红）。
  本文件只留**必须在真实设备/真实交互里才能判断**的两项。

## 验证项

| 验证步骤 | 预期结果 | 实际结果 | 状态 | 备注/证据 |
| --- | --- | --- | --- | --- |
| 1. 开触摸模式，同一方向快速连划 3~5 次（每次间隔约 0.5~1s，短于动作片长） | 每次都换动作、**不出现"划了没反应"**；不再有"必须等上一个动作播完"的等待感 | | 待验证 | 修复前：片长 1.9~4.1s 内全部被静默丢弃 |
| 2. 让 AI 说一句带动作的台词（`[motion:…]`），在它演动作时快速滑动 | 剧本动作**不被划掉**（继续演），工具条上的手指按钮**闪一下**（≤0.2s、不出现文字/弹窗） | | 待验证 | 修复前：同样静默，用户无法区分"没收到"与"故意不抢" |
| 3. 连划观感：注意抢占那一帧有没有"抽搐/瞬移" | 动作从旧姿态顺势换过去，无可见跳变 | | 待验证 | 桌面端实测跨越帧间增量 2.943° ≤ 动作自身峰值 11.853° |
| 4. 回归：触摸模式单指仍是视线、双指仍平移缩放；点角色仍有 Tap 动作 | 与改动前一致 | | 待验证 | 机制面已由 verify-touch-mode / verify-tap 覆盖 |

待验证。

## 待跟进

- 若第 1 项仍出现"划了没反应"：记录**模型名、方向、距上一次滑动的大致间隔**，
  回来读 `lvGestureSeq`（是否前进）/ `lvPreemptGesture`（是否抢占）/ `lvRejectScript`（是否剧本地盘）三个计数即可定位。
- 若第 2 项按钮闪烁观感太弱/太吵：按 auto-human 的既定口径，上线后看 `lvRejectScript` 占比再决定是否砍掉这层 UI。
